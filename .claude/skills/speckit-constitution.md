# Spec Kit: Constitution

The Constitution is the highest level of authority in the project. It defines the "Laws of the Land" that all subsequent specs, plans, and code must follow.

## Workflow

1. **Define Core Principles**:
   - Establish the architectural philosophy (e.g., "Prefer composition over inheritance").
   - Define coding standards (e.g., "Use functional components and Tailwind CSS").
   - Set naming conventions (e.g., "Kebab-case for files, PascalCase for components").

2. **Establish Global Constraints**:
   - Define performance targets.
   - Specify security requirements.
   - List banned libraries or patterns.

3. **Maintenance**:
   - Review the Constitution whenever a fundamental change in project direction occurs.

## Artifact
Create or update `.claude/constitution.md`. This file should be referenced at the start of every new feature spec to ensure alignment.

## Success Criteria
- A clear, concise `.claude/constitution.md` exists.
- The AI can refer to this file to resolve high-level architectural disputes.
